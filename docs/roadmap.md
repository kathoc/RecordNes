# これから

`docs/spec.md` に書いた仕様のうち、まだ手を付けていないものと、その順番。

## 1. Android

`src/` はブラウザで動く web アプリとして書いてあり、ネイティブ機能は
`src/platform/types.ts` の `PlatformBridge` だけを通る。Android 対応で書くのは
その実装 1 つだけで済む設計にしてある。

必要なもの。

- Capacitor で包む（`@capacitor/android`）
- `CapacitorBridge`: ファイル選択と保存を Storage Access Framework へ
- 動画書き出し: ffmpeg の実行ファイルを置けないので、`MediaCodec` を叩くプラグインか
  WebCodecs を使う。ここだけは Electron 版と作りが変わる
- 画面に合わせた操作系。仮想パッドと、片手でも届く巻き戻しボタン

## 2. ブラウザ版の動画書き出し

WebCodecs (`VideoEncoder` + `AudioEncoder`) と mp4 の多重化で、ffmpeg 無しでも
書き出せるようにする。Android 版とも共有できる。

## 3. 入力表示の焼き込み

`ExportSettings.overlayInput` を用意だけしてある。押しているボタンを画面の隅に
重ねて書き出す。スーパープレイ動画では、何を押しているかが見えると価値が上がる。

## 4. 記録の編集

- 2 つの記録をつなぐ（面ごとに分けて撮り、後でつなぐ）
- 目印の間を切り出す
- 入力列を直接直す（フレーム単位の微調整）

## 5. まだ確かめていないこと

- **NROM と MMC3 以外のマッパー**。コアは 100 種類以上に対応しているが、
  こちらで決定性とセーブステートを確かめたのは 2 本だけ。手元の ROM を増やして
  `tools/jam-scan.mjs` を回す
- **PAL の ROM**。フレームレートと音声の本数が変わるので、書き出しの
  フレームレート合わせに手当てが要る
- **バッテリーバックアップのあるゲーム**。今は必ず電源投入の状態から始める
  （記録の再現性を保つため）。既存のセーブから始めたい場合は、ステートを
  読み込んで「そこから新しい記録」にする経路を使う
- **実機のコントローラー**。開発機に繋がっていないため、Gamepad API の経路は
  コードを追って組んだだけで、実物での確認をしていない
